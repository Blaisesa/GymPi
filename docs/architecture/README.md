# Architecture documentation

GymPi's architecture is developed through approved decisions and thin vertical slices.

- Durable decisions are recorded in `../adr/`.
- `../../PROJECT.md` defines the current product scope and system summary.
- `../../ENGINEERING.md` defines design, scalability, and delivery principles.
- `system-architecture.md` defines the approved runtime, code, data, and deployment boundaries.
- `module-map.md` defines capability ownership and growth rules.

Detailed data models, trust boundaries, and deployment views will be added when the relevant behaviour is planned. They are not created speculatively.
